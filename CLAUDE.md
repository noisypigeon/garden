# CLAUDE.md

This repo holds `templates/` — versioned, reusable templates published at
`pigeon.dev`, hoisted out of `noisypigeon/noisypigeon` by ADR-0154 (which kept
the `templates/…` paths byte-identical, so every pre-existing tag prefix,
workflow glob and short URL kept working unchanged) — and, since ADR-0156,
`pigeon.dev/src`: the Zola site that publishes those templates' redirect
pages, module overview pages and release posts, generated by
`pigeon.dev/generate-module-redirects.sh` and deployed to GitHub Pages by
`.github/workflows/pigeon-dev-pages.yml`. Hoisting the site into the same repo
as the tags it describes is what let that generator go back to reading
`templates/` off local disk instead of a fetched clone, and what let
`resolve-theme.sh` go back to a live `"main"` symlink for this site
specifically (`noisypigeon.com`, a separate repo, still needs a clone and
still gets one via its own `fetch-templates.sh`).

`templates/` itself has two independently versioned tracks:

- `templates/terraform/<provider>/<module>/` — 13 Terraform modules (Scaleway,
  Backblaze), tagged `templates/terraform/<provider>/<module>/vX.Y.Z`, each
  self-contained (own `versions.tf`, `README.md`, `CHANGELOG.md`). Consumed via
  short `pigeon.dev/modules/<provider>/<module>/vX.Y.Z` URLs that resolve
  through go-getter's HTTP discovery protocol to a `git::` source against this
  repo. The public URL path is `modules/…`, **not** `templates/terraform/…` —
  that namespace is a stable public interface, deliberately decoupled from
  internal layout (ADR-0109/0110).
- `templates/zola-site/` — a reusable Zola theme, tagged
  `templates/zola-site/vX.Y.Z`, consumed by a site setting
  `[extra].theme_version` and running `resolve-theme.sh` out of a clone of this
  repo. The script resolves everything relative to its own location, so it
  works wherever the clone lands.

See `README.md` for the consumption contract and `templates/terraform/README.md`
for the module index.

## Where the decisions live

ADRs live in this repo, under `adr/`, one directory per decision domain. The
`pigeon.dev` domain is `adr/pigeon.dev/PD-NNNN-<slug>.md` — hoisted here from
`noisypigeon/noisypigeon/docs/adr/` by ADR-0157 and renamed from
`adr/infrastructure/` with `PD-` IDs by PD-0160. Its sibling is
`adr/noisypigeon.com/NPC-NNNN-<slug>.md` (NPC-0000), the blog repo's own
decisions. Before making an architectural or interface change here, read the
relevant ADRs and keep new work consistent with them; if a change would
contradict one, flag it rather than silently diverging, and prefer writing a new
ADR over undocumented drift.

Filing a `pigeon.dev` ADR, by hand — `adr-new.sh` lives in
`noisypigeon/noisypigeon` and still hardcodes the old path, so it cannot create
these (PD-0160):

- **Number**: max+1 **within `adr/pigeon.dev/`**, which is the only sequence it
  shares. `0136`, `0138` and `0156` are each used twice already, from parallel
  branches — check before claiming a number.
- **Filename and H1 agree**: `PD-0160-<slug>.md` holds `# PD-0160: <title>`.
- **Author is always** `Willow Graysen ([@noisypigeon](https://github.com/noisypigeon)).`
  Records dated before 2026-10-03 say `Willow Finch` and are correct as filed;
  do not retrofit them.
- **Sections**: `## Context` / `## Decision` / `## Consequences` /
  `## Out of scope`, optionally then `## Verification`. No YAML frontmatter, and
  no index or registry to update — there isn't one.
- **Citations**: cite `PD-NNNN`. Bare `ADR-NNNN` in existing prose means the
  same record — PD-0160 renamed the files and H1s but grandfathered the ~1,100
  in-text citations, so the two spellings are aliases for this corpus.
- Genuinely-deferred `## Out of scope` items get a GitHub issue filed against
  `noisypigeon/noisypigeon` (ADR-0031); permanent design boundaries do not.

The load-bearing ones for this repo: ADR-0154 (the split that brought
`templates/` here; its prefix→repo mapping, which kept 20 legacy `modules/*`-era
tags resolving against `noisypigeon/noisypigeon`, was retired by PD-0160 step 0
once nothing pinned them — every module tag now lives here, under one prefix),
ADR-0037/0093/0110 (this directory's prior homes and why old tags still
resolve), ADR-0109/0136 (the short-URL redirect
mechanism and its move to the `pigeon.dev` host), ADR-0119/0120/0153 (the
modules' current composition shape), ADR-0112/0113/0114/0139 (the theme, its
versioning, and its resolution), and ADR-0156 (hoisting `pigeon.dev/src` here
and cutting its deploy over from a Scaleway bucket to GitHub Pages).

## Dev cycle

Every change ships through a labelled PR — see the `release-pr` skill, which is
the discipline, not just a convenience. The PR body becomes the changed unit's
`CHANGELOG.md` entry and GitHub Release notes **verbatim**, and exactly one
`release:*` label drives the version bump. There is no human reviewer and no
branch protection.

Every merged PR gets exactly one line in the root `CHANGELOG.md`, under a
`## YYYY-MM-DD` section, newest first; a PR that changes a releasable unit
additionally gets its full PR body in that unit's own `CHANGELOG.md`. That is
PD-0160's contract, and `.github/scripts/root-changelog.sh` is the single
implementation both writers call. `template-release.yml` writes the line for
module and theme releases; `root-changelog.yml` runs on every merged PR and
covers everything else (`pigeon.dev/`, `templates/` without a release, `adr/`,
`.github/`, root docs), standing down when `template-release.yml` owns the
entry. The root file's `<!-- entries below; newest first -->` marker is where
entries get inserted — the script refuses to write without it.

On merge, `template-release.yml` tags each changed module (or the theme),
updates its `CHANGELOG.md` and the root one, cuts a GitHub Release, and then
dispatches whichever site deploy(s) that release actually affects. A module
release dispatches `pigeon-dev-pages.yml` **in this repo** — `pigeon.dev/src`
lives here now (ADR-0156), so its redirect pages and release posts regenerate
from this repo's own tags and `CHANGELOG.md` files with no cross-repo call. A
`templates/zola-site` release additionally dispatches `zola-sites-deploy.yml`
**in `noisypigeon/noisypigeon`** with `site=noisypigeon.com`, since that's the
one remaining site this repo doesn't host; that dispatch needs
`BOT_GITHUB_TOKEN` to carry `actions: write` on that repo, and if it fails the
theme is tagged here but `noisypigeon.com` never rebuilds against it.
`module-docs.yml` separately regenerates each module's input/output table on
any `.tf` change.

A change spanning a module and its consumer is two PRs in two repos: this one
merges, tags and deploys first, then the consumer's `source =` pin is bumped in
`noisypigeon/noisypigeon`. For local iteration before tagging, a consumer can
point `source =` at a relative path into a sibling clone of this repo instead.

## Commands

- `mise run fmt-terraform` / `mise run fmt-check-terraform` — format / check
  formatting for Terraform files.
- `mise run pigeon-dev-build` / `mise run pigeon-dev-serve` — build / serve
  `pigeon.dev/src` with Zola (resolves the theme, regenerates redirect/
  overview/release pages, then `zola build`/`zola serve`).
